# HTTP와 HTTPS 데이터 전송 방식 및 HTTPS 필요성

---

# 1. 왜 HTTPS가 중요한가?

우리가 사용하는 웹 서비스는 로그인, 결제, 개인정보 조회 등 민감한 데이터를 주고받는다.

하지만 HTTP는 데이터를 암호화하지 않고 그대로 전송한다.

예:

ID: rain  
PW: 1234abcd

중간에서 데이터를 가로채면 내용을 그대로 확인할 수 있다.

예시:

- 공용 와이파이 환경
- 로그인 정보 탈취
- 결제 정보 유출

예:

500 Internal Server Error가 아니라

개인정보 유출 = 실제 피해 발생

> HTTPS는 단순 보안 기능이 아니라 실무 서비스의 기본 조건이다.

---

# 2. HTTP와 HTTPS 차이

HTTP:

사용자 - > ID: rain PW:1234 -> 인터넷 -> 서버

중간 공격자:

ㅋㅋ 비밀번호 보임

HTTPS:

사용자
↓
암호화

af#29dj!a0x

↓
인터넷
↓
서버 복호화

중간 공격자:

?????

핵심:

HTTP → 평문 전송

HTTPS → 암호화 전송

---

# 주요 차이

|구분|HTTP|HTTPS|
|---|---:|---:|
|데이터 형태|평문|암호화|
|보안|없음|SSL/TLS 적용|
|주소|http://|https://|
|브라우저|안전하지 않음|🔒 자물쇠|

---

# 3. HTTPS 핵심 기능

HTTPS는 단순히 암호화만 하는 기술이 아니다.

암호화

무결성

인증

3가지를 제공한다.

---

## (1) 암호화

목적:

남이 읽지 못하게 함

예:

1234

↓

x89dk21

실제 사례:

- 쇼핑몰 카드번호
- 로그인 비밀번호
- 계좌 정보

---

## (2) 무결성

의미:

보낸 내용이 중간에 바뀌지 않았는지 확인

예:

사용자:

10만원 송금

↓

중간 공격자

↓

100만원 송금

HTTPS:

"어? 데이터가 변경됨"

변조 감지

핵심:

데이터 위조 방지

---

## (3) 인증

의미:

상대 서버가 진짜인지 확인

예:

가짜 사이트:

naver-login-real.com

브라우저:

너 진짜 네이버 맞아?

서버:

인증서 제출

브라우저:

🔒 통과

핵심:

피싱 사이트 방지

---

# 4. 실제 서비스 사례

은행 서비스

- 계좌번호
- 송금정보
- 금융정보 보호

쇼핑몰

- 카드정보 보호
- 개인정보 보호

로그인 서비스

- ID/PW 보호

최근 브라우저:

HTTP 사이트 → 안전하지 않음 표시

---

# 5. 실제 브라우저 동작

주소창:

🔒 https://

의미:

- 암호화
- 데이터 위변조 방지
- 인증 완료

---

# 6. 결론

HTTP는 데이터를 평문으로 전송한다.

HTTPS는 SSL/TLS 기반으로 암호화, 무결성, 인증 기능을 제공한다.

실무에서는 개인정보, 결제, 로그인 기능이 많기 때문에 HTTPS는 선택이 아니라 필수이다.
