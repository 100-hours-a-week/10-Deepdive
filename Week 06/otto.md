# RAGAS로 RAG 시스템의 문제 원인 진단하기

검색은 맞는데 답이 틀렸을 때 vs. 답은 그럴듯한데 근거가 틀렸을 때

`Faithfulness` · `Answer Relevancy` · `Context Precision` · `Context Recall`

---

## 1 · 왜 RAGAS가 필요한가

### RAG는 두 단계, 그래서 문제도 두 곳

**① Retrieval (검색)**
질문과 관련된 문서를 DB에서 찾아오는 단계
→ "무엇을 근거로 답할까?"

**② Generation (생성)**
찾아온 문서를 근거로 LLM이 답을 쓰는 단계
→ "근거로 답을 잘 썼나?"

> **답이 이상할 때, "LLM이 틀렸다"로 끝내면 안 된다.**
> RAGAS = RAG *Assessment*. RAG의 검색 품질과 답변 품질을 점수로 평가하는 도구입니다.
> 정답 문장을 일일이 사람이 채점하지 않고, 네 가지 지표로 **문제가 검색 쪽인지 생성 쪽인지**를 갈라서 보여 줍니다.

---

## 2 · 4가지 핵심 지표

> 외우기 핵심: **답변을 보는 2개 = 생성 / 컨텍스트를 보는 2개 = 검색**

### GENERATION 진단

**Faithfulness (충실도)**
- 평가 대상: 답변이 검색된 근거에 충실한가 (지어내지 않았나)
- 낮으면: 근거에 없는 내용 생성 = 환각(hallucination)
- 단계: Generation

**Answer Relevancy (답변 관련성)**
- 평가 대상: 답변이 질문에 제대로 답하는가
- 낮으면: 동문서답·장황·핵심 누락으로 질문을 빗나감
- 단계: Generation

### RETRIEVAL 진단

**Context Precision (정밀도)**
- 평가 대상: 검색 결과 상단이 질문과 관련 있는가
- 낮으면: 관련 없는 문서가 상위에 섞임 = 노이즈 많음
- 단계: Retrieval

**Context Recall (재현율)**
- 평가 대상: 필요한 근거를 빠짐없이 가져왔는가
- 낮으면: 정답에 필요한 핵심 근거가 검색에서 누락됨
- 단계: Retrieval

---

## 3 · 상황 A — 검색은 맞는데, 답변이 틀렸다

**예시**

| 구분 | 내용 |
|---|---|
| Q · 사용자 질문 | "우리 환불 정책상 환불 가능 기간은?" |
| C · 검색된 Context | 정책 문서: "구매 후 **14일** 이내 환불 가능" *(정답 근거 포함)* |
| A · LLM 답변 | "구매 후 **30일** 이내 환불 가능합니다." *(근거와 다른 숫자)* |

**지표 진단**

| 지표 | 결과 | 이유 |
|---|---|---|
| Faithfulness | 낮음 | 근거(14일)와 다른 내용을 생성 → 충실도 급락 |
| Answer Relevancy | 중·높음 | 질문엔 답함(기간을 말함) → 관련성은 살아 있음 |
| Context Precision | 높음 | 검색된 정책 문서는 질문과 정확히 관련 |
| Context Recall | 높음 | 정답 근거(14일)가 컨텍스트에 들어 있음 |

> **결론: 검색은 정상. 문제는 Generation 단계 (환각).**
> 검색 지표 두 개는 멀쩡한데 충실도만 무너짐 → 검색이 아니라 프롬프트·모델·디코딩을 손봐야 한다.

---

## 4 · 상황 B — 답변은 자연스러운데, 검색이 틀렸다

**예시**

| 구분 | 내용 |
|---|---|
| Q · 사용자 질문 | "이 약의 권장 복용량은?" |
| C · 검색된 Context | 약의 '효능·부작용' 문단만 검색 *(복용량 근거 없음)* |
| A · LLM 답변 | "보통 **하루 2회, 1회 1정** 복용합니다." *(그럴듯하지만 근거 없음)* |

**지표 진단**

| 지표 | 결과 | 이유 |
|---|---|---|
| Faithfulness | 낮음 | 컨텍스트에 없는 복용량을 답함 → 근거 부재 |
| Answer Relevancy | 높음 | 문장은 질문에 맞아 보임 → 관련성은 높게 나옴 *(← 속기 쉬운 함정)* |
| Context Precision | 낮음 | 검색 상단이 질문(복용량)과 어긋남 |
| Context Recall | 낮음 | 필요한 복용량 근거가 아예 누락됨 |

> **결론: 답은 그럴듯해도 근거 없음. 문제는 Retrieval 단계.**
> 답변 관련성은 높아 보여도 검색 지표 둘이 무너짐 → LLM이 아니라 검색기·청크 전략·임베딩을 손봐야 한다.

---

## 5 · 결론 — 틀린 게 아니라, 어디서 틀렸는지를 본다

| 지표 | 평가 대상 | 낮을 때 의미 | RAG 단계 | 개선 방법 |
|---|---|---|---|---|
| **Faithfulness** | 답변이 근거에 충실한가 | 근거에 없는 내용 생성 (환각) | Generation | 프롬프트 강화·근거 인용 강제·디코딩 조정 |
| **Answer Relevancy** | 답변이 질문에 답하는가 | 동문서답·장황·핵심 누락 | Generation | 질문 재진술·출력 형식 지정·답변 압축 |
| **Context Precision** | 상위 검색결과가 관련 있나 | 관련 없는 문서가 상위에 섞임 | Retrieval | 리랭커 도입·top-k 축소·쿼리 재작성 |
| **Context Recall** | 필요한 근거를 다 가져왔나 | 핵심 근거가 검색에서 누락 | Retrieval | 청크 전략 개선·임베딩 교체·top-k 확대 |

> ✅ **RAG 성능 문제는 "LLM이 틀렸다"로 끝나지 않는다.**
> Retrieval인지 Generation인지 나눠 보고, RAGAS 4지표를 *함께* 보면 문제의 원인을 정확히 진단할 수 있다.
