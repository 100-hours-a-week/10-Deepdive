# Retrieval 검색 품질이 LLM 응답 품질에 미치는 영향

---

## 1. 왜 검색 품질이 중요할까?

RAG는 **검색(Retrieval) -> 생성(Generation)** 순서로 동작한다.

이때 LLM은 자기가 외운 지식이 아니라, **검색해 온 문서를 근거로** 답을 만듭니다.

```
RAG = 오픈북 시험
LLM = 학생
검색된 문서 = 학생이 펼쳐 본 책
```

학생이 아무리 똑똑해도, 펼친 책이 잘못되면 답을 틀림

따라서 검색 품질이 곧 응답 품질의 한계를 정함

```
검색 품질이 답변 품질의 천장이다
-> 검색이 70점이면, 생성을 잘해도 답변은 70점을 넘기 어려움
```

검색이 잘못되는 경우는 크게 3가지로 나뉩니다.

---

## 2. 경우 1: 관련 문서가 검색되지 않은 경우

### 정의
질문에 답할 근거 문서가 검색 결과(Top-K)에 하나도 포함되지 않은 상황입니다

### 발생 원인
* 질문과 문서의 표현 차이 ("감기" 질문 <-> 문서엔 "상기도 감염")
* 청킹 오류로 정보가 분리됨
* 임베딩 모델이 의미를 제대로 못 잡음

### 응답 품질
근거 자체가 없으므로 두 갈래로 망가집니다.

```
갈래 A: LLM이 "모른다"고 답함
        -> 틀리진 않지만 쓸모 없음

갈래 B: LLM이 지어냄 (환각)
        -> 가장 위험. 그럴듯하게 틀려서 사용자가 속음
```

### 진단 지표
Context Recall이 낮게 나타난다. (필요한 근거를 못 가져옴)

### 한 줄 요약
출발부터 글러서 세 경우 중 가장 치명적이다. 생성 단계로는 못 살린다.

---

## 3. 경우 2: 관련성은 있지만 근거가 부족한 경우

### 정의
관련 문서를 찾긴 했지만, 질문에 정확히 답할 핵심 정보가 빠져 있는 상황이다.

### 예시
```
질문   : "RAG 커리큘럼은 몇 개 교재로 구성?"
검색됨 : "RAG는 검색과 생성을 합친 기법이다..."
        -> RAG 얘기는 맞지만 '36개'라는 숫자가 없음
```

### 응답 품질
* 두루뭉술하게 답함 ("여러 교재로 구성됩니다" - 숫자 못 댐)
* 질문의 일부만 답함 (불완전 답변)
* 핵심을 못 짚고 주변만 맴돔

### 진단 지표
Context Recall이 애매하게 낮다. (완전 0은 아니나 핵심 정보가 빠짐)

Answer Relevancy도 함께 떨어질 수 있다.

### 한 줄 요약
방향은 맞지만 부실한 답이다. 맞는데 싱거운 요리에 가깝다.

---

## 4. 경우 3: 불필요한 문서가 함께 검색된 경우

### 정의
관련 문서는 찾았지만, 무관한 문서까지 검색 결과에 섞여 들어온 상황이다.

### 예시
```
질문   : "어댑터즈가 뭐야?"
검색됨 : 어댑터즈 소개      (O)
        + 저작권 문구       (X)
        + 무관한 표 조각    (X)
        + 딴 페이지 메뉴    (X)
```

### 응답 품질
* LLM이 노이즈에 휘둘려 옆길로 샌다
* 답이 산만해지고 초점이 흐려진다
* 노이즈를 진짜 근거로 착각해 틀리기도 한다

### 진단 지표
Context Precision이 낮게 나타난다. (검색 결과의 순도 저하)

### 한 줄 요약
Garbage In, Garbage Out. 좋은 문서가 노이즈에 묻힌다.

---

## 5. 세 경우 비교

| 경우 | 상황 | 응답 결과 | 낮아지는 지표 |
|---|---|---|---|
| 1. 미검색 | 근거 자체 없음 | "모름" or 환각 | Context Recall |
| 2. 근거 부족 | 근거 불완전 | 두루뭉술 / 일부만 | Recall + Relevancy |
| 3. 노이즈 | 불필요 문서 섞임 | 산만 / 옆길로 샘 | Context Precision |

---

## 6. 경우별 처방

각 경우는 떨어지는 지표가 다르므로, 처방도 다르다.

| 경우 | 문제 지표 | 처방 |
|---|---|---|
| 1. 미검색 | Recall 낮음 | 임베딩 교체, 청킹 개선, Query Expansion, HyDE |
| 2. 근거 부족 | Recall 애매 | 청크 크기 조정, Top-K 늘리기 |
| 3. 노이즈 | Precision 낮음 | Reranking, 전처리 강화 |

```
검색 기법 -> 평가 -> 진단 -> 처방
이 흐름이 하나의 사이클로 이어진다
```

---

## 7. 결론 및 요약

검색 품질이 응답 품질의 천장이라는 점은 세 경우 모두에서 동일하게 드러난다.

```
경우 1 -> 천장이 바닥 (재료 없음)
경우 2 -> 천장이 낮음 (재료 부실)
경우 3 -> 천장은 있으나 시야 흐림 (노이즈)
```

같은 "검색 실패"라도 망가지는 방식과 떨어지는 지표가 다르며,
이를 구분해야 올바른 처방이 가능하다.

결국 RAG 품질을 높이려면 생성보다 검색을 먼저 점검해야 한다.
