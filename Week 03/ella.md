## 1. NumPy란?

- **Numerical Python**의 약자
- Python의 기본 리스트보다 **훨씬 빠른 효율적인 수치 연산**을 지원하는 라이브러리

```python
import numpy as np
```

---

## 2. NumPy 배열 생성 

NumPy에서는 배열을 생성하여 데이터를 저장하고 관리합니다.

### 기본 생성 방법: array() 함수를 사용

```python
# 리스트로부터 생성
a = np.array([1, 2, 3])          # 1차원 배열
b = np.array([[1, 2], [3, 4]])   # 2차원 배열 (행렬)

# 자동 생성
np.zeros((3, 3))    # 모든 값이 0인 3x3 배열
np.ones((2, 4))     # 모든 값이 1인 2x4 배열
np.arange(0, 10, 2) # 일정 간격의 숫자 배열 생성 [0, 2, 4, 6, 8]
np.linspace(0, 1, 5) # 특정 구간을 균등하게 나눈 배열 생성 [0, 0.25, 0.5, 0.75, 1.0]
```

### 핵심 속성

| 속성 | 설명 | 예시 |
|------|------|------|
| `ndim` | 차원 수 | `2` |
| `shape` | 각 차원의 크기 | `(3, 4)` |
| `dtype` | 데이터 타입 | `float64` |
| `size` | 전체 원소 수 | `12` |

## 3. 배열 연산 — 벡터화(Vectorization)

### Python 리스트 vs NumPy 비교

```python
# Python 리스트 방식 (반복문 필요)
result = [x * 2 for x in [1, 2, 3, 4, 5]]

# NumPy 방식 (한 줄로 처리)
a = np.array([1, 2, 3, 4, 5])
result = a * 2  # → [2, 4, 6, 8, 10]
```

> ✅ NumPy는 **원소별 연산**을 기본으로 함  
> ✅ 내부적으로 최적화된 C 코드가 실행되므로 **수십 배 빠름**

### 기본 산술 연산

```python
a = np.array([1, 2, 3])
b = np.array([10, 20, 30])

a + b   # → [11, 22, 33]
a * b   # → [10, 40, 90]
a ** 2  # → [1, 4, 9]
np.sqrt(a)  # → [1.0, 1.414, 1.732]
```

## 4. 브로드캐스팅(Broadcasting)

### 개념

> **shape이 다른 배열 간의 연산을 자동으로 처리**하는 NumPy의 핵심 메커니즘

서로 크기가 다른 배열끼리도, 특정 규칙을 만족하면 연산할 수 있도록 **자동으로 작은 배열을 늘려서** 크기를 맞춰주는 기능

### 브로드캐스팅 3가지 규칙
 
**규칙 1. 차원 수가 다르면 → 앞에 1을 붙여서 맞춤**
 
```
b의 shape: (3,)  →  앞에 1 추가  →  (1, 3)
```
 
> 짧은 쪽을 늘려서 두 배열의 차원 수를 같게 만드는 단계
 
---
 
**규칙 2. 차원 크기가 1이면 → 상대방 크기로 복사해서 확장**
 
```
A: (2, 3)
b: (1, 3)  →  1인 자리를 2로 확장  →  (2, 3)
```
 
> 크기 1인 차원은 "같은 값을 반복한다"고 보면 됨
 
---
 
**규칙 3. 그래도 크기가 다르면 → 오류**
 
```
(3,) vs (2,)  →  1이 없고 3 ≠ 2  →  ValueError
```
 
> 두 배열의 각 차원 크기가 "같거나, 둘 중 하나가 1"이어야만 브로드캐스팅 가능

---

### Case 1 — 배열 + 스칼라

```python
a = np.array([1, 2, 3])
a + 10
# → 10이 [10, 10, 10]으로 확장되어 계산
# → [11, 12, 13]
```

```
[1, 2, 3]
   + 10       →    + [10, 10, 10]
-----------        ---------------
[11, 12, 13]       [11, 12, 13]
```

---

### Case 2 — 2D 배열 + 1D 배열

```python
A = np.array([[1, 2, 3],
              [4, 5, 6]])   # shape: (2, 3)

b = np.array([10, 20, 30])  # shape: (3,)

A + b
# NumPy는 b 배열을 각 행에 자동으로 적용시킴
# → [[11, 22, 33],
#     [14, 25, 36]]
```

```
행렬 A (2×3)         벡터 b (1×3 → 2×3으로 확장)
[[ 1,  2,  3]    +   [[10, 20, 30]
 [ 4,  5,  6]]        [10, 20, 30]]
```

---

### Case 3 — 열벡터 + 행벡터

```python
col = np.array([[1], [2], [3]])  # shape: (3, 1)
row = np.array([10, 20, 30])     # shape: (3,) → (1, 3)

col + row
# → [[11, 21, 31],
#     [12, 22, 32],
#     [13, 23, 33]]
```

> 두 배열이 **서로 다른 축 방향으로** 확장되어 2D 결과를 만들어냄

---

### 오류 예시

```python
np.array([1, 2, 3]) + np.array([1, 2])
# ValueError: operands could not be broadcast together
# shapes (3,) and (2,) — 1이 없고 크기도 다름
```

## 5. 왜 빠른가? — 내부 동작 원리
 
### 이유 1 — Python은 원소마다 해석, NumPy는 배열 전체를 한 번에 실행
 
Python은 코드를 실행할 때 한 줄씩 해석(인터프리팅)하면서 동작함.  
반복문으로 원소 1개를 처리할 때마다 Python 인터프리터가 개입함.
 
NumPy는 내부적으로 **C언어로 미리 컴파일된 코드**가 실행됨.  
Python의 해석 과정 없이 바로 CPU가 실행 → 그만큼 빠름.
 
```
Python 반복문:  [원소1 처리] → [원소2 처리] → [원소3 처리] → ...  (매번 통역사가 개입)
NumPy 벡터화:  [배열 전체를 C코드로 한 번에 처리]             (통역사 없음 원어민임)
```
 
---
 
### 이유 2 — 메모리에 데이터가 "붙어서" 저장됨
 
Python 리스트는 각 원소가 메모리 여기저기 **흩어져서** 저장됨.  
원소를 하나씩 꺼낼 때마다 메모리를 찾아다녀야 함.
 
NumPy 배열은 데이터가 메모리에 **일렬로 쭉 붙어서** 저장됨.  
CPU가 한 번에 쭉 읽어올 수 있어서 훨씬 효율적.
 
```
Python 리스트:  [주소A] [주소F] [주소C] [주소Z] ...  (흩어져 있음)
NumPy 배열:    [1][2][3][4][5][6][7][8] ...         (연속으로 붙어 있음)
```
 
---
 
### 실제 속도 차이
 
```python
import numpy as np
import time
 
n = 1_000_000  # 백만 개 원소
 
# NumPy
a = np.arange(n)
start = time.time()
result = a * 2
print(f"NumPy:  {time.time() - start:.5f}초")
 
# Python 리스트
lst = list(range(n))
start = time.time()
result = [x * 2 for x in lst]
print(f"Python: {time.time() - start:.5f}초")
 
# 결과 예시
# NumPy:  0.00200초
# Python: 0.08000초  →  약 40배 차이
```
 
> 데이터가 클수록 차이는 더 벌어짐 (10배 → 100배도 가능)

## 6. 정리

```
NumPy 핵심 3가지

1. ndarray     → shape/dtype이 고정된 고성능 배열
2. 벡터화 연산  → 반복문 없이 배열 전체를 한 번에 처리
3. 브로드캐스팅 → shape이 달라도 규칙에 맞으면 자동 확장 연산
```

> NumPy가 데이터 분석(Pandas), 머신러닝(scikit-learn), 딥러닝(PyTorch/TensorFlow)의  
> **공통 기반**인 이유 — 빠르고, 유연하고, 메모리 효율적이기 때문
