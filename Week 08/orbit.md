### 1. 일반 Edge vs 조건부 Edge


| 구분          | 일반 엣지                            | 조건부 엣지                                                                 |
| :---------- | :------------------------------- | :--------------------------------------------------------------------- |
| 다음 노드 결정 시점 | 코드 작성 시점 (고정)                    | 그래프 실행 시점(동적)                                                          |
| 결정 주체       | 개발자                              | 라우팅 함수 + State                                                         |
| 코드          | graph.add_node("search", search) | 예) graph.add_conditional_edges("judge", route, ["search", "generate"]) |

일반 Edge : 한 노드 실행 끝나면 다음 노드 지정하는, 
			(비유) : 일방통행 길

조건부 Edge : 한 노드 실행 끝나면 그때의 State값을 보고 다음 노드를 그때 결정함,
			(비유) : 갈림길 + 이정표 

==여기서 핵심 포인트 : 결정 주체가 개발자와 라우팅 함수 + State==

[judge] ------> [search] (검색 필요하면)
		 |---> [generate] (필요 없으면)

### 2. 동적 제어 동작 방식

노드 실행이 끝나면 -> 라우팅 함수가 호출되고 -> 현재 State 값을 읽어 -> 다음 노드의 **이름(문자열)** 을 반환한다. LangGraph는 그 이름의 노드로 흐름을 보냄

```
[judge 실행]
->
route(state) 실행
->
state["needs_search"] 확인
->
"search" or "generate" 반환
->
해당 노드로 이동
```

같은 그래프라도 State 값에 따라 매번 다른 경로로 실행될 수 있다 — 이것이 "동적 제어!!!"
### 3. 직접 구현 사례

8주차 위클리 챌린지 2번 (RAG Agent)에서 직접 구현 해봤습니다.

7주차 RAG를 StateGraph로 마이그레이션한 뒤, "검색"하던 구조에 판단 노드와 조건부 엣지를 추가해 Agent로 확장했습니다.

```
start -> judge -> (route가 결정)
			 ㄴ "search" -> search -> generate -> end
			 ㄴ "generate" -> generate -> end 
```

#### 핵심 코드

```python
# 실제 위클리챌린지 코드 : LLM이 검색 필요 여부를 판단해 State에 기록

# 과제 2번 판단 노드 추가

def judge(state: RAGState) -> dict:

# 질문보고 문서 검색이 필요한지 판단

judge_prompt = ChatPromptTemplate.from_messages([

("system",

"질문이 개발 기술 문서(파이썬, 자료구조, 알고리즘, 객체지향)"

"검색이 필요한 질문이면 'yes', "

"검색이 필요없으면 'no'로 답하세요."

"다른 말은 하지말기."),

("human", "{question}"),

])

chain = judge_prompt | llm | StrOutputParser()

reply = chain.invoke({"question": state["question"]})

needs = "yes" in reply.strip().lower()

return {"needs_search" : needs}
```


```python
# 라우팅 함수 : State를 보고 다음 노드 "이름"을 반환(노드 X)
def route(state: RAGState) -> dict:

"""needs_search 값 보고 다음 노드 이름 반환"""

if state["needs_search"]:

return "search"

else:

return "generate"
```


```python
#조건부 엣지 등록
graph.add_conditional_edges("judge", route, ["search", "generate"]) # 갈림길
```

#### 실행 결과


| 입력       | judge 판단          | 경로                           | 답변                                                            |
| -------- | ----------------- | ---------------------------- | ------------------------------------------------------------- |
| 파이썬이 뭐야? | needs_search=True | judge -> search -> generate  | 파이썬은 **1991년 네덜란드계 소프트웨어 엔지니어인 귀도 반 로섬이 발표한 고급 프로그래밍 언어**입니다. |
| 안녕안녕     | needs_search=True | judge -> generate ( 검색 스킵하기) | [개별 답잠 질문] 안녕하세요! 저도 반갑습니다. 😊                                |

같은 그래프, 같은 코드이지만 질문에 따라 다른 경로로 실행됨


### 4. 조건 판단이 모호하거나 잘못 설계되면?(잘못 설계 시 문제 4가지)

#### 문제 1 . 오분류 : 잘못된 경로 실행

```
"파이썬이 뭐야?" 를 검색 불필요로 오판하면
-> 근거 문서 없이 답변 생성 함 -> 환각(hallucination) 위험 업

"안녕" 를 검색 필요로 오판하면
-> 불필요한 검색 실행 -> 비용,지연 낭비
```

==라우팅이 틀리면 그 뒤의 모든 실행이 잘못된 전제 위에서 돌아감==

#### 문제 2. 모호한 기준 : 비일관성

==LLM으로 판단하는 경우, 판단 프롬프트가 모호하면 같은 질문에도 실행마다 다른 경로를 탈 수 있음==

```
-> 결과 재현 불가, 디버깅 어려움
-> 동일 입력에 매번 다른 출력이 나오는 문제 : temperature 등 생성 설정과도 연결됨
```

#### 문제 3. 등록되지 않은 노드 이름 반환

```python
def route(state):
	return "serch" # 오타 발생! 등록 안된 이름이지요
	
# -> 그래프 실행 자체가 에러로 중단
```

라우팅 함수의 반환값은 
```python
add_conditional_edges(...)
```
여기에 등록한 노드 목록과 정확히 일치해야함

#### 문제 4. 순환 구조에서 무한 루프
```
LangGraph는 이전 노드로 되돌아가는 순환을 허용
-> 종료 조건 판단이 잘못되면 A->B->A->B.. 무한 반복을 하게 됨
-> LLM 호출 비용 폭증 + 응답은 영영 반환 안됨
```

#### 직접 겪은 문제 

Agent 전환으로 질문단 LLM 호출이 1회 -> 2회 (judge + generate)로 늘면서 무료 티어 분당 5회 / 일일 20회 한도에 걸림 (429 RESOURCE_....).
판단 노드 추가는 흐름 제어 능력을 주는 대신 호출 비용이 늘어난다는 트레이드오프가 있음

트레이드오프 (trade off) : 하나의 목표를 달성하거나 이득을 얻으려면 다른 측면의 품질이나 속성을 포기해야 하는 상충 관계를 의미

 + 헤이스가 데일리 스크럼에서 질문하신 임베딩에서의 한도 초과였냐는 질문에서 재 답변을 드린다면은.. 임베딩에서는 문제 없었고 생성쪽에서 한도 초과였습니다.


### 5. 좋은 설계 조건 

1. 판단 기준을 명확히 : 판단 프롬프트에 출력 형식을 강하게 지시하기
2. 반환 가능한 값을 제한 : 라우팅 함수는 등록된 노드 이름만 반환하도록
3. 반복 구조엔 안전 장치 : 최대 반복 횟수 등으로 무한 루프 차단
4. 비용 인식 : 판단에 LLM을 쓰면 호출 수가 늘어남 (rate limit 고려하기)

### 6. 한 줄 요약

조건부 엣지 = " If 문이 달린 엣지 " 그래프의 유연함은 라우팅 판단의 품질에 달려있고, 판단이 무너지면 그 뒤의 모든 흐름이 무너짐!
