# 위치 인코딩 (Positional Encoding) 

---

## 1. 왜 위치 인코딩이 필요할까?

RNN은 입력을 시간 순서대로 하나씩 처리하기 때문에 위치 정보가 자연스럽게 반영된다.

반면 Transformers는 모든 토큰을 동시에 병렬 처리한다.


```
"나는 학교에 간다"
-> Transformers는 "나는", "학교에", "간다"를 동시에 처리함
-> 순서를 알 수 없음
-> 모델 입장에서는
["나는", "학교에", "간다"] 
["간다", "나는", "학교에"] 
구별이 안 됨
```

따라서 위치 정보를 별도로 주입해야함

```
입력 = 토큰 임베딩 + 위치 인코딩
```

위치 인코딩 방식은 크게 3가지로 발전했습니다.

---

## 2. 트렌스포머 기본 위치 인코딩

### 정의 
원 논문 "Attention Is All You Need"(2017)에서 제안한 방식으로,
사인/코사인 함수를 이용해 각 위치마다 고유한 벡터를 생성하여 토큰 임베딩에 더하는 방식이다.

### 수식 
$$
PE(pos, 2i) = sin(pos / 10000^{2i/d_{model}})
$$
$$
PE(pos, 2i+1) = cos(pos / 10000^{2i/d_{model}})
$$

* pos: 토큰의 위치 (0, 1, 2, ...)
* i: 벡터의 차원 인덱스
* d_model: 임베딩 벡터의 차원 수

짝수의 차원에는 sin, 홀수 차원에는 cos을 적용함.

차원마다 다른 주기를 사용해 각 위치마다 고유한 패턴을 만들어냄.

### 동작 원리
각 위치 번호를 입력하면 -1 ~ 1 사이의 값으로 이루어진 벡터가 생성됩니.

위치가 아무리 커져도 값이 무한히 커지는 것이 아니라 안정적이다.

```
position 1 → [sin(1/1), cos(1/1), sin(1/100), cos(1/100), ...]
position 2 → [sin(2/1), cos(2/1), sin(2/100), cos(2/100), ...]
position 3 → [sin(3/1), cos(3/1), sin(3/100), cos(3/100), ...]
```
서로 다른 주기 덕분에 각 위치마다 고유한 패턴이 만들어짐

#### 이해를 위해 수식을 풀어내는 과정
$$
PE(pos, 2i) = sin(pos / 10000^(2i/d_model))
$$
```
i = 0 (0번 차원) 일 때
-> sin(pos / 10000^(0/512))
-> sin(pos / 10000^0)
-> sin(pos / 1)

i = 1 (2번 차원) 일 때
-> sin(pos / 10000^(2/512))
-> sin(pos / 약 100)

i = 2 (4번 차원) 일 때
-> sin(pos / 10000^(4/512))
-> sin(pos / 약 1000)
```

이걸 그대로 위치별로 대입

```
position 1, i=0 → sin(1/1)
position 1, i=1 → cos(1/1)   <- cos은 홀수 차원
position 1, i=2 → sin(1/100)
```
즉, 수식에 i = 0, 1, 2 ... 와 pos = 1, 2, 3 ... 을
직접 대입해서 예시로 풀어낸 것.

### 코드
```python
import torch
import math
 
def positional_encoding(max_len, d_model):
    pe = torch.zeros(max_len, d_model)
    position = torch.arange(0, max_len).unsqueeze(1).float()
    div_term = torch.exp(
        torch.arange(0, d_model, 2).float() * -(math.log(10000.0) / d_model)
    )
    pe[:, 0::2] = torch.sin(position * div_term)  # 짝수 차원: sin
    pe[:, 1::2] = torch.cos(position * div_term)  # 홀수 차원: cos
    return pe
 
pe = positional_encoding(max_len=100, d_model=512)
print(pe.shape)  # torch.Size([100, 512])
```

### 장단점
* 장점: 학습 파라미터 없음, 훈련 시 보지 못한 긴 시퀀스도 처리 가능
* 단점: 학습 데이터에 최적화되지 않아 표현력에 한계가 있음

## 3. BERT의 학습 가능한 절대위치 인코딩

### 정의 
BERT에서 사용한 방식으로, 위치별 벡터를 고정 수식이 아닌 학습을 통해 직접 최적화하는 절대 위치 인코딩

### 동작 원리
각 위치(0번, 1번, 2번 ...)마다 고유한 벡터를 임베딩 테이블로 관리합니다
토큰 임베딩, 위치 임베딩, 세그먼트 임베딩 세 가지를 더해 입력으로 사용합니다

```
입력 = 토큰 임베딩 + 위치 임베딩(학습됨) + 세그먼트 임베딩
 
예시:
[CLS] Startupcode is a company [SEP]
  0       1        2  3    4     5    <- 위치 번호
```

위치 임베딩 테이블은 nn.Embedding(max_position, d_model) 형태로 구현되며
역전파를 통해 학습 데이터에 맞게 최적화된다.

### 기본 PE와의 차이점
기본 PE는 수식으로 고정된 값을 사용하지만,
BERT PE는 학습 과정에서 데이터에 맞게 위치 벡터 자체가 업데이트됩니다.

```
기본 PE: 위치 벡터 = 수식으로 계산 (고정)
BERT PE: 위치 벡터 = 학습으로 최적화 (변동)
```
 
### 장단점
* 장점: 학습 데이터에 최적화되어 표현력이 높음
* 단점: 최대 512토큰 제한 (학습 시 정한 길이에 강하게 의존), 그 이상은 처리 불가

## 4. RoPE (Rotary Position Embedding)
 
### 정의
RoPE는 토큰 임베딩에 위치 정보를 덧셈이 아닌 회전 행렬을 곱해 인코딩하는
상대 위치 기반 인코딩 방식이다. LLaMA, GPT-NeoX 등 최신 LLM에서 주로 사용된다.
 
### 동작 원리
기존 방식은 위치 벡터를 토큰 임베딩에 더했다.
 
```
기존: 입력 = 토큰 임베딩 + 위치 벡터
RoPE: 입력 = 토큰 임베딩 x 회전 행렬(위치)
```
 
회전 행렬을 사용하면 어텐션 계산 시 두 토큰 간의 거리(상대 위치)가 자동으로 반영된다.
 
```
Q · K = f(토큰A, 위치m) · f(토큰B, 위치n)
      -> 결과에 (m - n) 즉 상대 거리 정보가 포함됨
```

두 위치의 차이(m-n)만 어텐션에 영향을 주기 때문에
절대 위치가 아닌 상대 거리를 학습하게 된다.
 
### 기존 방식과의 차이점
기본 PE와 BERT PE는 절대 위치 기반이라 "이 토큰은 몇 번째"를 표현한다.
RoPE는 상대 위치 기반이라 "이 토큰과 저 토큰이 얼마나 떨어져 있는지"를 표현한다.
 
```
절대 위치: "나는"은 1번 위치, "학교에"는 2번 위치
상대 위치: "나는"과 "학교에"는 1칸 차이
```

### 장단점
* 장점: 학습 길이보다 긴 시퀀스에도 일반화 잘 됨, 상대 거리 표현으로 문맥 이해 우수
* 단점: 구현이 기존 방식보다 복잡함
---
 
## 5. 세 가지 비교
 
| 항목 | 기본 PE (Sinusoidal) | BERT PE | RoPE |
|---|---|---|---|
| 방식 | 사인/코사인 함수 | 학습 가능한 임베딩 | 회전 행렬 |
| 학습 파라미터 | 없음 | 있음 | 없음(또는 적음) |
| 위치 기준 | 절대 위치 | 절대 위치 | 상대 위치 |
| 길이 제한 | 없음 | 512 토큰 | 없음 |
| 사용 모델 | 원 Transformer | BERT | LLaMA, GPT-NeoX |
| 등장 시기 | 2017 | 2018 | 2021 |

## 6. 결론 및 요약
 
세 가지 위치 인코딩은 같은 문제를 서로 다른 방식으로 해결한다.
 
```
기본 PE  -> 수식으로 고정된 위치 표현 (빠르고 간단)
BERT PE  -> 학습으로 최적화된 위치 표현 (표현력 높지만 길이 제한)
RoPE     -> 회전으로 상대 거리 표현 (긴 시퀀스에 강함, 최신 LLM 표준)
```
 
위치 인코딩은 단순히 "몇 번째 토큰인지"를 알려주는 것을 넘어,
모델이 문장의 구조와 문맥을 얼마나 잘 이해할 수 있는지에 직접 영향을 준다.
최신 LLM에서 RoPE가 표준이 된 이유는 긴 문서 처리와 상대적 문맥 이해에 강하기 때문이다.
