# 배치 정규화 vs 레이어 정규화 비교 분석

> 두 정규화 방법의 원리, 차이, 사용처 비교 분석

---

## 1. 배치 정규화 (Batch Normalization)

### 배치 정규화가 뭔가

딥러닝은 층이 수십 개다. 앞 층 가중치가 바뀌면 뒷 층이 받는 입력 분포가 계속 달라진다.
배치 정규화는 이 문제를 해결하기 위해, 같은 배치 안에서 같은 피처끼리 묶어서 정규화하는 방법이다.

**"같은 피처, 여러 샘플"** — 열(↕) 방향으로 묶어서 평균·분산 계산

| 샘플 | 피처1 | 피처2 | 피처3 |
|------|-------|-------|-------|
| 샘플1 | **0.5** | 3.1 | 7.2 |
| 샘플2 | **1.2** | 2.8 | 8.1 |
| 샘플3 | **0.8** | 3.5 | 7.5 |
| 샘플4 | **0.3** | 2.9 | 6.9 |

→ 피처1 열(0.5, 1.2, 0.8, 0.3)을 세로로 모아서 평균·분산 계산 후 정규화

### 어떻게 동작하나 (수식)

    μ = (1/m) Σ xᵢ          ← 배치 평균
    σ² = (1/m) Σ (xᵢ - μ)²  ← 배치 분산
    x̂ = (x - μ) / √(σ² + ε) ← 정규화
    y = γ × x̂ + β           ← γ,β: 표현력 복원 파라미터

마지막 γ(감마)와 β(베타)는 정규화로 줄어든 표현력을 모델이 스스로 복원하는 학습 파라미터다.

### 강점

- 학습이 빠르고 안정적으로 됨
- 학습률을 크게 잡아도 학습이 잘 됨
- 배치가 충분히 크면 정확한 평균·분산으로 효과가 뛰어남

### 약점

- **배치가 작으면 평균이 부정확해짐**
  배치 2개면 그 2개가 우연히 극단값이면 평균이 완전 틀려짐
- 학습할 때와 추론할 때 동작이 달라서 `model.train()` / `model.eval()` 모드 전환 필수
  (학습 중 저장한 이동 평균을 추론 때 꺼내 씀)

### 어디에 쓰이나 — CNN · 이미지

이미지는 크기가 항상 고정이다. 32×32 이미지면 항상 32×32.
피처 수가 항상 같으니까 열 방향으로 묶는 게 가능하다.
배치도 32~128개씩 크게 쓸 수 있어서 평균이 안정적이다.

> 대표 모델: **ResNet, VGG**

## 2. 레이어 정규화 (Layer Normalization)

### 레이어 정규화가 뭔가

배치 정규화가 열 방향이라면, 레이어 정규화는 방향이 반대다.
같은 샘플 안에서 모든 피처를 묶어서 정규화한다.

**"한 샘플, 모든 피처"** — 행(↔) 방향으로 묶어서 평균·분산 계산

| 샘플 | 피처1 | 피처2 | 피처3 |
|------|-------|-------|-------|
| **샘플1** | **0.5** | **3.1** | **7.2** |
| 샘플2 | 1.2 | 2.8 | 8.1 |

→ 샘플1의 값(0.5, 3.1, 7.2)을 가로로 모아서 평균·분산 계산 후 정규화

### 어떻게 동작하나 (수식)

    μ = (1/H) Σ xⱼ          ← 피처 평균
    σ² = (1/H) Σ (xⱼ - μ)²  ← 피처 분산
    x̂ = (x - μ) / √(σ² + ε) ← 정규화
    y = γ × x̂ + β           ← γ,β: 표현력 복원 파라미터

> 수식 구조가 배치 정규화와 동일. 차이는 m(배치 수)으로 나누냐, H(피처 수)로 나누냐. 묶는 방향만 다른 거다.

### 강점

- **배치 크기와 완전히 무관** — 배치가 1개여도 동일하게 동작
- 학습할 때와 추론할 때 동작이 완전히 동일 → 별도 처리 불필요, 버그 없음
- 데이터 크기가 가변이어도 문제없음

### 약점

- 이미지처럼 피처 간 관계보다 샘플 내 관계가 중요한 경우엔 배치 정규화보다 상대적으로 비효율

### 어디에 쓰이나 — Transformer · NLP

**이유 1 — 문장 길이가 다 달라서**

| 문장 | 피처1 | 피처2 | 피처3 | 피처4 |
|------|-------|-------|-------|-------|
| "밥 먹었어?" | 0.5 | 1.2 | 0.3 | - |
| "오늘 점심에 밥 먹었어?" | 0.5 | 1.2 | 0.3 | 0.8 |

배치 정규화는 피처4 열을 모아야 하는데, 짧은 문장엔 피처4가 없어서 열 방향 묶기 자체가 불가능하다.
레이어 정규화는 각 문장 안에서만 계산하니까 길이 상관없다.

**이유 2 — 배치를 크게 못 써서**

GPT, BERT는 파라미터가 수백억 개라 GPU 메모리가 부족해서 배치를 1~8개 수준으로 작게 쓸 수밖에 없다.
배치 정규화는 이 상황에서 평균이 엉터리가 된다.

> 대표 모델: **GPT, BERT**

## 3. 비교 분석

| 비교 항목 | 배치 정규화 | 레이어 정규화 |
|-----------|------------|--------------|
| 정규화 방향 | 열↕ (피처 기준) | 행↔ (샘플 기준) |
| 배치 크기 의존 | 클수록 안정적 | 완전 무관 |
| 추론 시 동작 | 저장된 이동 평균 사용 | 학습과 동일하게 계산 |
| 데이터 크기 | 고정 크기에 적합 | 가변 크기도 OK |
| 주 사용처 | CNN, ResNet, VGG | Transformer, GPT, BERT |

---

## 4. 결론

> **둘 다 목적은 같다** — 각 층의 입력 분포를 안정시켜 학습을 빠르고 안정적으로 만드는 것.
> 차이는 어느 방향으로 묶어서 정규화하느냐.
> 그 방향 차이 하나가 적합한 데이터 유형을 완전히 갈라놓는다.

| 상황 | 선택 |
|------|------|
| 데이터 크기 고정 + 배치 크게 가능 | ✅ 배치 정규화 |
| 데이터 크기 가변 + 배치 작을 수밖에 없음 | ✅ 레이어 정규화 |
